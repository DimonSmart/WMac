# ENG-0004.rule-project-and-distribution

## Rule

Xcode-проект содержит автоматизированные конфигурации Debug и Release и universal arm64 + x86_64 сборку. Info.plist задаёт стабильный bundle ID и локализованное имя WMac!. Пример `app.wmac.WMac` не фиксирует точное значение идентификатора. Режим menu bar/agent допустим при подтверждённой тестированием корректной работе окон настроек.

Debug использует постоянную локальную code-signing identity из игнорируемого `LocalSigning.xcconfig`, подключённого только к Debug. Однократный setup повторно использует действительный Apple Development сертификат или создаёт один локальный self-signed сертификат с ключом в пользовательском Keychain. Self-signed сертификат не добавляется в системное доверие. Xcode Run и локальная сборка берут одну Debug identity; скрипт сборки прекращает работу, если настроенный сертификат недоступен, и не подменяет его ad-hoc подписью. Debug сохраняет Hardened Runtime; `com.apple.security.get-task-allow` включён только для WMac Debug, дополнительных runtime exceptions нет. У WMac Debug отключена упаковка Xcode в вспомогательную debug dylib: без Apple Team ID dyld отклоняет её при проверке library validation.

Release подготавливается для GitHub Releases как universal DMG с перетаскиванием в Applications. Developer ID Application подпись, notarization и stapling не являются требованиями поставки. Release остаётся явно ad-hoc подписанным независимо от локального Debug сертификата; это не выдаётся за подпись доверенного разработчика или подтверждение Gatekeeper. Hardened Runtime сохраняется, а release-проверки подтверждают отсутствие debug entitlements. Документация честно описывает возможное системное подтверждение запуска загруженного приложения; автоматическое изменение Gatekeeper, quarantine или системного доверия запрещено.

В репозитории должны быть README.md с практической информацией о сборке, установке, разрешениях и ограничениях, а также исполняемый набор тестов. Нормативное описание продукта хранится в `.idd/intent/`, инженерные ограничения — в `.idd/engineering/`; README не должен дублировать их в виде отдельных архитектурных, матричных или ручных тестовых документов. Отчёты о выполненных проверках и временные доказательства не являются нормативной документацией. Функциональные ограничения не маскируются обходными хаками.

## Applicability

Conditional

## Applies when

Создание или изменение проекта, конфигураций сборки, bundle metadata, релизной упаковки или документации для разработчиков.
