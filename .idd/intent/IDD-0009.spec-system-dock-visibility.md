# IDD-0009.spec-system-dock-visibility

## Intent

WMac может **по явному согласию** пользователя временно скрывать штатный Dock, сохраняя системный процесс Dock и все функции macOS. По умолчанию функция выключена как в новой установке, так и при миграции старых настроек. Это best-effort скрытие, а не официальная замена Dock или запрет его показа при любых обстоятельствах.

## Пользовательское поведение

- В Настройки → Общие доступен переключатель «Скрывать системный Dock, пока работает WMac». При первом включении подтверждение описывает изменение системных предпочтений, сохранение исходных значений и перезапуск Dock.
- Успешный статус отображается только после подтверждённой записи и применения параметров. Ошибка сопровождается диагностикой.
- В меню значка WMac в строке macOS и в основном меню приложения всегда отображаются команды «Скрыть системный Dock» и «Восстановить системный Dock». Недоступные по состоянию команды отключены. Первое включение из меню требует такого же подтверждения, как в настройках; повторное скрытие при разрешённом режиме может повторить неудачную попытку без нового подтверждения.
- Команда восстановления доступна, когда режим включён в настройках или есть незавершённая транзакция; она отключает сохранённую опцию. При ошибке сохранения пользовательского выбора явное восстановление не должно приводить к автоматическому повторному скрытию в той же сессии. Скрытие не запускается без готовых панелей WMac.
- Ручное «Скрыть панели WMac» временно возвращает Dock; при повторном показе панелей режим возобновляется, если он включён. Отсутствие панелей над fullscreen не означает ручное скрытие.
- Для функции не нужны Terminal, администратор, Accessibility или Screen Recording.

## Системные ограничения

Изменяются **только** предпочтения com.apple.dock в согласованном домене current user / any host:

| Key | Temporary value |
| --- | --- |
| autohide | true |
| autohide-delay | 1000.0 |
| autohide-time-modifier | 0.0 |

Отсутствующие изначально ключи при восстановлении удаляются. Типы исходных значений сохраняются. Если параметр после применения изменён извне, WMac не перезаписывает новое значение; сообщается о конфликте. Host-specific overrides и управляемые политиками значения не должны обходиться. Реальное изменение предпочтений допускает один контролируемый перезапуск Dock, не периодические kill/restart. Не меняются размер/положение Dock, закреплённые программы, эффекты запуска, горячие углы и прочие параметры.

Механизм основан на публичном CoreFoundation Preferences API; параметры задержки Dock не являются гарантированным публичным контрактом Apple. При несовместимости необходим безопасный отказ.

## Восстановление и аварийная безопасность

Независимо от settings.json сохраняется атомарная транзакция в ~/Library/Application Support/WMac/SystemDockVisibilityState.plist: версия, сессия, владелец, состояние, домен, исходные и временные значения. До любых изменений должен быть получен снимок и подтверждение готовности одноразового WMacDockWatchdog.

Watchdog отслеживает именно процесс текущей сессии, а при неожиданном завершении восстанавливает значения и прекращает работу. Межпроцессная блокировка и проверка идентификатора сессии запрещают конкурентные транзакции и запоздалое восстановление поверх новой сессии. При обычном завершении, отключении функции и ручном восстановлении выполняется тот же compare-and-restore. При ошибке записи требуется откат; при неуспешном восстановлении файл состояния сохраняется для следующего запуска.

При следующем запуске WMac восстанавливает незавершённую транзакцию **до** нового применения режима, в том числе после аварийного выключения питания. Без последующего запуска WMac после потери питания восстановления гарантировать нельзя. При повреждении состояния запрещено угадывать значения: пользователь должен получить объяснение необходимости ручного восстановления.

## Не входит в этап

Подмена процесса Dock, переадресация системных анимаций сворачивания, собственные системные жесты, Mission Control/Spaces/Launchpad и принудительное резервирование места в workspace.

## Приёмка

Автоматические проверки на подменяемом backend не должны затрагивать реальные предпочтения macOS. Проверяются миграции v1/v2 → v3, opt-in по умолчанию off, точное восстановление значений/отсутствия, идемпотентность, конфликты, ошибочное состояние, отсутствие helper, блокировка двух сессий. Ручная проверка на macOS 14+ включает команды скрытия и восстановления из обоих меню (в том числе при скрытых панелях WMac), подтверждение/отмену, повторную попытку после ошибки, Dock при крае экрана не менее пяти секунд, выключение/выход, kill -9 основного процесса, рестарт после незакрытой транзакции, скрытие/показ WMac, внешнюю правку предпочтений, fullscreen, RU/EN доступность и universal arm64/x86_64 helper внутри подписанного Release DMG.

Связанные интенты: IDD-0006, IDD-0007, IDD-0008. Архитектурное исключение: ENG-0003.
