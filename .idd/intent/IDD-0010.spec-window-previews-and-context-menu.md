# IDD-0010 — WMac: Window Previews & Context Menu

**Проект:** WMac  
**Тип:** Product & Engineering Intent  
**Платформа:** macOS 14+, Swift 6, AppKit  
**Статус:** готово к реализации  
**Предлагаемый файл:** `.idd/intent/IDD-0010.spec-window-previews-and-context-menu.md`

## 1. Цель

Реализовать удобный предпросмотр окон работающих приложений непосредственно через панель WMac по аналогии с панелью задач Windows 11.

Пользователь должен иметь возможность:

1. Навести курсор на иконку работающего приложения и после небольшой задержки увидеть список его окон.
2. Увидеть настоящие миниатюры содержимого окон, если macOS разрешает захват.
3. Выбрать конкретное окно непосредственно из popup.
4. Открыть аналогичный список через контекстное меню независимо от настройки автоматического показа.
5. Управлять индивидуальным поведением предпросмотра для отдельных приложений.
6. Пользоваться более структурированным контекстным меню.

Все функции должны использовать публичные macOS API, существующие механизмы WMac и работать с произвольными совместимыми приложениями без хардкода.

**Главный принцип:** идентификация и выбор окон остаются независимыми от получения изображений. Скриншот — необязательное визуальное дополнение, а не основание для управления окном.

## 2. Место функции в архитектуре WMac

### 2.1. Существующие компоненты

Необходимо переиспользовать:

- `ProcessMonitor` — обнаружение работающих экземпляров.
- `TaskbarCoordinator` — связь экземпляров, закреплений и кнопок.
- `TaskbarDelegate` — действия пользователя и контекстное меню.
- `AccessibilityService` — обнаружение и управление окнами.
- `WindowReference` — стабильная идентичность управляемого окна.
- `ProcessButton` — отображение кнопки экземпляра.
- `DisplayCoordinator` — панели на нескольких дисплеях.
- `SettingsController` и `SettingsStore` — пользовательские настройки.

Не создавать второй независимый реестр процессов или управляемых окон.

### 2.2. Инварианты

Сохранить:

- Идентичность экземпляра `(PID, launchDate)`.
- Идентичность приложения через существующий `AppDefinition`.
- Идентичность окна через `WindowReference.id`.
- Правило одной кнопки на каждый отображаемый экземпляр.
- Существующие действия левой, средней и правой кнопок мыши.
- Модель закреплений и временных кнопок.
- Безопасную деградацию при недоступном Accessibility.

Каждая кнопка показывает окна только своего конкретного экземпляра, даже если запущено несколько процессов с одинаковым bundle ID.

Один popup может быть открыт только для одного экземпляра в каждый момент времени, независимо от количества дисплеев.

### 2.3. Отношение к другим Intent

Новый `IDD-0010` расширяет `IDD-0003`, `IDD-0005`, `IDD-0007` и `IDD-0008`.

В `IDD-0005` запрет Screen Recording относился к первоначальному MVP. Новый Intent вводит отдельную последующую функциональность, где Screen Recording допустим исключительно для добровольно включённых миниатюр.

Необходимо согласовать соответствующие нормативные формулировки, не удаляя исторические требования первоначального MVP и не создавая противоречащие источники истины.

Новый Intent добавить в `.idd/intent/INDEX.md`.

## 3. Popup предпросмотра окон

### 3.1. Автоматическое открытие

При наведении на кнопку запущенного экземпляра начинается таймер.

**Задержка по умолчанию — 450 мс.**

Автоматический показ зависит от режима:

| Режим | Поведение |
|---|---|
| Automatic | Показывать при одном и более управляемых окнах |
| Disabled | Не показывать автоматически |

Значение по умолчанию — `Automatic`.

Popup не открывается автоматически, если:

- экземпляр завершился;
- окно нельзя перечислить из-за отсутствия Accessibility;
- подтверждённо нет управляемых окон;
- началось перетаскивание;
- открыто контекстное меню;
- курсор покинул кнопку до окончания задержки;
- соответствующая панель скрыта;
- кнопка изменила привязку к экземпляру.

Отсутствие Accessibility не должно инициировать системный запрос разрешения при обычном наведении.

### 3.2. Явное открытие

Контекстное меню содержит команду **«Показать окна…»**.

Команда работает независимо от `Hover previews`.

При явном вызове допускается показ информационного состояния:

- нет открытых окон;
- требуется Accessibility;
- список временно недоступен;
- выбранный экземпляр завершился.

Если меню вызвано из основной панели, popup привязывается к соответствующей кнопке.

Если команда вызвана из меню WMac в строке меню и исходная кнопка недоступна, используется подходящее расположение на активном дисплее. Не допускается привязка к невидимому или уже уничтоженному `NSView`.

### 3.3. Содержимое

Popup показывает:

- название приложения;
- номер экземпляра, если экземпляров несколько;
- количество управляемых окон;
- карточки окон;
- миниатюру либо заглушку;
- название каждого окна;
- индикатор активного окна;
- индикатор свёрнутого окна.

Карточка должна содержать доступное полное название окна для VoiceOver и tooltip.

Активное окно визуально выделяется.

Свёрнутое окно остаётся доступным для выбора.

Технические, системные, вспомогательные и неуправляемые окна не добавляются исключительно ради наличия изображения в ScreenCaptureKit.

### 3.4. Порядок окон

Карточки должны иметь стабильный порядок в течение одного открытия popup.

Первоначальный порядок соответствует порядку управляемых окон из `AccessibilityService`.

При смене фокуса обновляется выделение, но карточки не переставляются.

При изменении заголовка обновляется соответствующая карточка.

При закрытии окна карточка удаляется после подтверждения актуальным AX-снимком.

Новые окна добавляются без произвольной перестановки существующих.

### 3.5. Размеры и внешний вид

Ориентировочный размер изображения: **220 × 140 pt**.

Изображение масштабируется с сохранением пропорций. Не допускается произвольное растяжение или обрезка значимой части окна.

При небольшом количестве окон карточки располагаются горизонтально.

Для большого количества окон применяется ограниченный по ширине прокручиваемый список. Это основной вариант реализации; произвольный перенос карточек в несколько строк не требуется.

Popup должен:

- использовать системные цвета и оформление;
- поддерживать светлую и тёмную темы;
- корректно отображаться на Retina;
- не выходить за доступные границы дисплея;
- не перекрывать системную строку меню;
- учитывать расположение WMac;
- по возможности иметь визуальную связь с исходной иконкой.

Размер popup ограничивается видимой областью дисплея.

При недостатке места панель может менять положение относительно кнопки.

### 3.6. Сосуществование с tooltip

Сейчас `ProcessButton` показывает стандартный tooltip с названием и экземпляром.

Новое поведение не должно приводить к одновременному появлению tooltip и popup.

При фактическом показе popup стандартная подсказка подавляется для соответствующей кнопки. После закрытия popup обычное поведение tooltip восстанавливается.

При отключённых hover-previews существующие подсказки работают без изменений.

## 4. Жизненный цикл popup

### 4.1. Переход курсора

Popup остаётся видимым, пока курсор находится:

- над исходной кнопкой;
- внутри popup;
- в области перехода между кнопкой и popup.

Переход от кнопки к карточкам не должен случайно закрывать панель из-за небольшого зазора.

После выхода из этих областей применяется задержка закрытия **250 мс**.

Повторное попадание курсора в область popup отменяет закрытие.

### 4.2. Условия закрытия

Popup закрывается при:

- выборе окна;
- нажатии Escape;
- открытии контекстного меню;
- начале перетаскивания;
- скрытии панели WMac;
- завершении соответствующего экземпляра;
- исчезновении исходной кнопки;
- переходе на другую кнопку после начала её обработки;
- потере актуальности панели или дисплея;
- существенном изменении контекста, делающем popup неактуальным.

Нельзя оставлять висящую панель после закрытия приложения.

### 4.3. Несколько мониторов

Если на разных дисплеях присутствуют кнопки одного экземпляра, они используют общие сведения об окнах.

Одновременно отображается только один popup.

При перемещении на другой дисплей прежняя панель закрывается, а новая появляется по обычным правилам.

Нельзя запускать повторные захваты одного окна независимо для каждого дисплея.

При отключении монитора popup закрывается и освобождает связанные ресурсы.

### 4.4. Анимации

Допускается короткая ненавязчивая анимация появления.

При системном `Reduce Motion` анимация выключается либо существенно сокращается.

Анимации не должны задерживать доступность карточек для нажатия.

## 5. Получение настоящих миниатюр

### 5.1. Системный API

Использовать `ScreenCaptureKit`.

Основные API:

- `SCShareableContent`
- `SCWindow`
- `SCContentFilter(desktopIndependentWindow:)`
- `SCStreamConfiguration`
- `SCScreenshotManager.captureImage(contentFilter:configuration:)`

Для первой реализации использовать захват одиночных кадров.

Постоянный `SCStream` не требуется.

Список доступных для захвата окон получать асинхронно с учётом ограничения конкретного экземпляра по PID.

Для поиска потенциально доступных окон, в том числе находящихся вне текущего экрана, можно использовать:

`SCShareableContent.excludingDesktopWindows(true, onScreenWindowsOnly: false)`

Это не гарантирует доступности всех свёрнутых окон или окон других Spaces.

### 5.2. Отображение

При открытии:

1. Получить подтверждённый список AX-окон.
2. Сразу показать карточки с названиями и заглушками.
3. Проверить разрешение на захват.
4. Получить доступные `SCWindow`.
5. Выполнить безопасное сопоставление.
6. Асинхронно захватить изображения подтверждённых окон.
7. Обновить соответствующие карточки, не пересоздавая весь popup.

Ошибка одного захвата не блокирует другие карточки.

Не допускается получать скриншот рабочего стола и затем приблизительно вырезать окно по координатам вместо захвата конкретного `SCWindow`.

### 5.3. Ограничения

Запрещено ради миниатюры:

- активировать другое приложение;
- поднимать окно;
- менять Space;
- разворачивать свёрнутое окно;
- перемещать окно;
- изменять размер окна;
- запрашивать захват экрана без разрешения пользователя.

Если окно перекрыто, предпочтителен независимый захват его содержимого.

Для fullscreen, защищённого содержимого, окон других Spaces и нестандартных окон допускаются системные ограничения.

### 5.4. Размер изображений

Захватывать изображение в размере, достаточном для отображения миниатюры на Retina, но не в полном разрешении исходного окна без необходимости.

Ориентир — приблизительно двукратный масштаб относительно размера отображаемой миниатюры.

Размер ограничивается централизованной конфигурацией.

Изображение должно декодироваться и отображаться без длительных операций на главном потоке.

### 5.5. Обновление

Первый показ карточки не должен ждать завершения ScreenCaptureKit.

При повторном открытии допускается немедленный показ ранее полученной миниатюры, если она ещё находится в кратковременном кэше.

Такое изображение обозначается как ранее полученный кадр до успешного обновления.

При успешном повторном захвате заменяется актуальным.

В первой версии не требуется постоянный периодический захват, пока popup открыт.

Допускается явное обновление и обновление при следующем открытии.

В отсутствие видимого popup фоновое получение новых кадров не выполняется.

### 5.6. Кэш

Кэшировать изображения только в оперативной памяти.

Ключ должен учитывать:

- `InstanceID`;
- `WindowReference.id`;
- подтверждённое соответствие конкретному `CGWindowID`;
- актуальность поколения запроса.

Рекомендуемые начальные ограничения:

- срок пригодности кэша для быстрого повторного показа — около 10 секунд;
- не более двух одновременных захватов;
- общий ориентировочный лимит изображений — 32 MiB;
- захват преимущественно видимых карточек;
- ограниченная очередь захвата при большом количестве окон.

Кэш очищается:

- при завершении экземпляра;
- при изменении идентичности окна;
- при отзыве разрешения;
- при отключении миниатюр;
- при достижении лимита памяти;
- при существенном изменении геометрии, если кадр больше не соответствует окну.

Изображения не сохраняются на диск.

## 6. Сопоставление AXUIElement и SCWindow

### 6.1. Проблема

`AccessibilityService` идентифицирует окна через `AXUIElement` и внутренний `WindowReference.id`.

ScreenCaptureKit идентифицирует графические окна через `CGWindowID`.

Публичного универсального и гарантированного преобразования `AXUIElement → CGWindowID` нет.

Запрещается использовать:

- `_AXUIElementGetWindow`;
- приватные SkyLight API;
- внутренние структуры WindowServer;
- порядок перечисления в качестве доказательства;
- один только заголовок окна;
- один только PID.

### 6.2. Дополнительные данные AX

Для сопоставления разрешается расширить получаемый AX-снимок сведениями:

- `kAXPositionAttribute`;
- `kAXSizeAttribute`;
- заголовок;
- минимизация;
- доступные роль и подроль.

Геометрия должна читаться внутри существующей контролируемой AX-границы, а не отдельными произвольными запросами из UI.

Не создавать второй независимый механизм перечисления AX-окон.

При ошибке получения геометрии карточка остаётся управляемой, но миниатюра может быть недоступна.

### 6.3. Координаты

Ввести единый механизм нормализации координат.

Он учитывает:

- координатные системы Accessibility и ScreenCaptureKit;
- границы нескольких дисплеев;
- дисплеи с отрицательными координатами;
- Retina;
- масштабирование;
- возможные отличия внешней рамки окна.

Не предполагать, что все API возвращают координаты в одной системе.

Нормализация должна быть проверена на реальных дисплеях.

### 6.4. Алгоритм

Для одного конкретного `InstanceID`:

1. Проверить актуальность процесса.
2. Получить текущие AX-окна.
3. Получить доступные `SCWindow` с точным PID.
4. Отфильтровать неподходящие графические окна.
5. Сравнить заголовки и нормализованную геометрию.
6. Рассчитать допустимых кандидатов.
7. Выполнить сопоставление один-к-одному.
8. Отклонить неподтверждённые и неоднозначные соответствия.

Сопоставление должно учитывать все конкурирующие окна экземпляра, а не обрабатывать каждое независимо по принципу первого подходящего кандидата.

Два разных `WindowReference` не могут одновременно получить один `CGWindowID`.

Для безопасного автоматического сопоставления недостаточно лишь единственного оставшегося кандидата, если доступные признаки слабы или противоречивы.

### 6.5. Результат

Компонент сопоставления возвращает:

- `matched` — однозначное достаточно надёжное соответствие;
- `unmatched` — соответствие отсутствует или недостаточно подтверждено;
- `ambiguous` — несколько допустимых соответствий.

Только `matched` позволяет привязать изображение к карточке.

Если несколько окон имеют одинаковые заголовки, одинаковую или близкую геометрию и не различаются другими надёжными публичными признаками, миниатюры не назначаются.

**Неверная миниатюра хуже отсутствующей миниатюры.**

### 6.6. Устаревание

Результат сопоставления действителен только для соответствующего снимка и поколения запроса.

При изменении экземпляра, состава окон или геометрии необходимо отклонять результаты, привязка которых больше не подтверждена.

Асинхронный результат захвата не должен заменять изображение другого окна после изменения состава карточек.

## 7. Безопасный выбор окна

### 7.1. Левый клик по карточке

При выборе:

1. Проверить актуальность `ButtonCapture`.
2. Проверить `(PID, launchDate)`.
3. Проверить существование исходного `WindowReference`.
4. Повторно подтвердить его идентичность актуальным AX-снимком.
5. При необходимости восстановить окно.
6. Поднять выбранное окно публичными средствами Accessibility.
7. Активировать точный экземпляр.
8. Закрыть popup.

Идентификатор `CGWindowID` не используется для управления.

### 7.2. Строгое переключение

Текущая реализация `AccessibilityService.select()` при некоторых ошибках может перейти к активации процесса целиком.

Для явного выбора конкретной карточки это поведение необходимо уточнить.

Если выбранное окно исчезло либо его идентичность не подтверждена:

- действие над другим окном не выполняется;
- произвольное окно того же процесса не выбирается;
- активация процесса не должна маскироваться под успешный выбор исходного окна;
- пользователю можно показать ненавязчивое сообщение о недоступности окна.

Рекомендуется сделать явный выбор строгой операцией, сохранив прежнюю безопасную деградацию для обычного переключения на экземпляр через кнопку Dock.

Одинаковая строгая семантика должна применяться при выборе конкретного окна из контекстного меню.

### 7.3. Свёрнутые окна

Свёрнутые AX-окна присутствуют в списке, если существующий `AccessibilityService` может ими управлять.

По клику применяется штатное восстановление.

Отсутствие миниатюры не блокирует восстановление.

Автоматическое разворачивание ради захвата запрещено.

### 7.4. Результат действия

Успешное действие должно означать, что целевое окно было восстановлено или поднято настолько, насколько это подтверждено API.

Если macOS не позволяет подтвердить результат, нельзя сообщать о гарантированном успехе.

WMac не должен оставаться активным поверх выбранного приложения после завершения действия.

## 8. Улучшение контекстного меню

### 8.1. Структура

Меню работающего экземпляра:

**Основные действия**
- Переключиться
- Новый экземпляр
- Показать окна…

**Окна**
- Текстовый список управляемых окон
- Отметка активного окна
- Индикатор свёрнутого окна

**Управление экземпляром**
- Скрыть
- Завершить этот экземпляр
- Завершить принудительно… (с подтверждением)

**Закрепление**
- Закрепить / Открепить
- Переместить влево / вправо
- Выбрать новое расположение приложения, если Pin повреждён

**Дополнительно**
- Показать в Finder
- Сведения: PID и путь

Группы разделяются стандартными `NSMenuItem.separator()`.

Недоступные действия скрываются или блокируются.

Меню незапущенного закреплённого приложения сохраняет существующие действия запуска, закрепления, восстановления пути и сведений. Пункт «Показать окна…» для него не требуется.

### 8.2. Окна в текстовом меню

Использовать тот же `AccessibilityService` и тот же механизм строгого выбора окна, что и в popup.

Не дублировать идентификацию.

Использовать подготовленный снимок данных.

**Не изменять произвольно структуру открытого `NSMenu` после начала tracking.**

Текущий асинхронный механизм очистки и повторного заполнения submenu необходимо переработать.

Рекомендуется предварительное асинхронное получение снимка, безопасное обновление перед открытием и обновление при следующем открытии.

Если данные ещё неизвестны, показывать корректное состояние «Загрузка…» или «Недоступно», не блокируя UI и не выдавая старые данные за актуальные.

Перед выполнением любого действия сохраняется повторная проверка идентичности.

### 8.3. Открытие popup из NSMenu

Команда «Показать окна…» должна открывать общий `WindowPreviewController`.

Открытие выполняется после завершения отслеживания контекстного меню.

Не допускается одновременное наложение активного `NSMenu` и автоматически открытого hover-popup.

### 8.4. Команды сторонних программ

Автоматическое извлечение пользовательских Dock-меню других приложений не входит в этот этап.

В частности, не требуется обнаруживать профили Terminal, пользовательские команды Finder или другие специфические действия.

Не использовать Accessibility для имитации чтения системного Dock-меню.

Поддержка расширений меню сторонних приложений может стать отдельным Intent.

## 9. Разрешения

### 9.1. Accessibility

Использовать существующий `AccessibilityPermissionService`.

Отсутствие разрешения:

- не блокирует запуск WMac;
- не блокирует переключение на экземпляр;
- не блокирует закрепления;
- не блокирует запуск и завершение процессов.

Автоматический hover не должен вызывать системный запрос Accessibility.

При явном обращении к управлению окнами разрешается показать штатное объяснение и предложить системную настройку.

### 9.2. Screen Recording

Для получения настоящих миниатюр необходимо системное разрешение захвата экрана.

Добавить в `Resources/WMac-Info.plist`:

`NSScreenCaptureUsageDescription`

С понятным пользовательским объяснением, что доступ используется исключительно для показа миниатюр окон в WMac.

При необходимости локализовать описание через существующие `InfoPlist.strings`.

### 9.3. Запрос разрешения

Проверка состояния может использовать публичный `CGPreflightScreenCaptureAccess()`.

Явный пользовательский запрос может использовать `CGRequestScreenCaptureAccess()`.

Отрицательный результат проверки не должен автоматически запускать новый запрос.

Запрос выполняется только после осознанного действия пользователя, например нажатия «Разрешить миниатюры».

Необходимо учитывать, что после предоставления разрешения macOS может потребовать перезапуск приложения.

Положительная предварительная проверка не гарантирует успешный захват конкретного окна. Фактические ошибки ScreenCaptureKit обрабатываются отдельно.

### 9.4. Отсутствие Screen Recording

Popup продолжает показывать названия и состояния AX-окон.

Вместо миниатюр используются заглушки.

В интерфейсе отображается ненавязчивое объяснение и действие перехода к разрешениям.

Обычное управление окнами не блокируется.

### 9.5. Отсутствие Accessibility

Если Accessibility недоступен, WMac не должен пытаться самостоятельно создавать управляемый список окон только из `SCWindow`.

Без достоверного соответствия AX-окну невозможно безопасно обещать выбор конкретной карточки.

Поэтому автоматический hover-preview в этом режиме не показывается.

Явная команда «Показать окна…» может показать информационную панель с объяснением необходимости Accessibility.

Не использовать ScreenCaptureKit как обходной механизм управления окнами.

### 9.6. Конфиденциальность

- Изображения обрабатываются локально.
- Скриншоты не отправляются в сеть.
- Скриншоты не записываются на диск.
- Изображения не используются для телеметрии.
- Пиксельные данные не попадают в журналы.
- Захват не выполняется без необходимости показа миниатюр.
- При отключении функции память с кэшированными изображениями освобождается.
- Не использовать скрытые механизмы обхода TCC.

## 10. Настройки

### 10.1. Глобальные настройки

Добавить раздел `Window Previews` / `Предпросмотр окон`.

Параметры:

**Hover previews**
- Automatic — по умолчанию
- Disabled

Ранее сохранённое глобальное значение Always ведёт себя как Automatic.

**Show window thumbnails**
- On — значение по умолчанию
- Off

Включённый параметр миниатюр означает предпочтение пользователя, а не автоматическое предоставление Screen Recording.

Если доступ не выдан, изображения не захватываются.

### 10.2. Индивидуальные настройки

Поддержать необязательное переопределение `Hover previews` для конкретного `AppDefinition`.

Значения:

- Use global setting
- Always
- Disabled

Переопределение Always для приложения включает предпросмотр при отключённом глобальном режиме; каждый экземпляр по-прежнему показывает только собственные окна.

Индивидуальная настройка применяется ко всем экземплярам данного `AppDefinition`, но каждый экземпляр по-прежнему показывает только собственные окна.

Настройка должна быть доступна через раздел приложений. Допускается соответствующий пункт в контекстном меню, если это не перегружает меню.

Не создавать отдельные настройки по PID.

### 10.3. Хранение

В текущем WMac используется `settings.json` версии 3.

Предлагается расширить схему до версии 4.

Требования:

- чтение существующих версий 1, 2 и 3;
- миграция без потери существующих настроек;
- значения по умолчанию для новых полей;
- сохранение существующих закреплений;
- отсутствие PID, WindowReference и CGWindowID в постоянном хранилище;
- сохранение прежней независимости состояния восстановления системного Dock.

Ошибочный или неподдерживаемый файл не должен silently перезаписываться.

### 10.4. Технические параметры

Задержки, лимиты параллельности, памяти и кэша централизовать.

Не обязательно выводить их в пользовательские настройки.

## 11. Архитектура реализации

### 11.1. Предлагаемые компоненты

**WindowPreviewController**
- Управление единственным открытым popup.
- Жизненный цикл и задержки.
- Привязка к кнопке.
- Состояния интерфейса.
- Отмена устаревших запросов.

**WindowPreviewView**
- Карточки.
- Заглушки и изображения.
- Выделение.
- Прокрутка.
- Клавиатура и Accessibility.

**WindowThumbnailService**
- Доступ к ScreenCaptureKit.
- Получение `SCWindow`.
- Захват одиночных кадров.
- Ограничение параллельности.
- Кэш и отмена.

**WindowMatcher**
- Сопоставление AX и SC.
- Нормализация геометрии.
- Обнаружение неоднозначности.
- Независимая тестируемая логика.

**WindowPreviewPreferences**
- Глобальный и индивидуальный режимы.
- Настройки изображений.
- Централизованные ограничения.

Это логические ответственности, а не требование создавать по одному большому классу на каждую сущность. Допускается объединение небольших компонентов, если границы остаются понятными.

### 11.2. Изменения AccessibilityService

Добавить доступные геометрические признаки в контролируемый AX-снимок.

Не раскрывать `AXUIElement` в UI-слое.

Обеспечить строгий выбор конкретного окна с отказом при устаревшей идентичности.

Сохранить существующий механизм переключения на процесс целиком для обычного нажатия на кнопку Dock.

### 11.3. Изменения ProcessButton

Добавить отслеживание входа и выхода курсора через штатные средства AppKit.

Корректно обновлять область отслеживания при изменении размеров и положения кнопки.

Не создавать отдельный таймер или отдельный popup для каждой кнопки.

Все события направлять общему контроллеру предпросмотра.

Существующие жесты и обработка drag-and-drop не должны изменять поведение.

### 11.4. UI-технология

Предпочтительна отдельная нативная popup-панель или эквивалентный компонент AppKit с контролируемым жизненным циклом.

Автоматический hover не должен менять активное приложение.

Для явного клавиатурного вызова допускается получение фокуса popup настолько, насколько требуется для доступной навигации.

При выборе окна управление передаётся целевому приложению.

### 11.5. Отмена и конкурентность

Каждое открытие popup получает отдельное поколение запроса.

При закрытии, смене экземпляра или повторном открытии старые поколения инвалидируются.

Асинхронный результат может обновить карточку только при совпадении:

- текущего поколения;
- `InstanceID`;
- `WindowReference.id`;
- актуального подтверждённого соответствия;
- состояния popup.

Отменять задачи, когда это возможно.

Если системный вызов уже не может быть прерван, его результат просто отбрасывается.

UI обновляется на MainActor. Захват и тяжёлая обработка изображения не блокируют главный поток.

Не допускать data races при Swift 6 strict concurrency.

## 12. Клавиатура и Accessibility UI

### 12.1. Клавиатура

Сохранить существующий Shift+F10 для контекстного меню кнопки.

Из этого меню должен быть доступен пункт «Показать окна…».

Внутри popup обеспечить:

- навигацию по карточкам с клавиатуры;
- Enter или Space для выбора окна;
- Escape для закрытия;
- предсказуемое управление фокусом.

Не вводить обязательные глобальные горячие клавиши или перехват системных комбинаций.

### 12.2. VoiceOver

Для каждой карточки должны быть доступны:

- название приложения;
- заголовок окна;
- состояние активного или свёрнутого окна;
- действие выбора;
- состояние отсутствующей миниатюры, если оно существенно.

Миниатюра не является единственным способом понять назначение карточки.

### 12.3. Размер целей

Интерактивные области должны оставаться удобными для мыши и доступной навигации.

Не размещать элементы слишком близко, чтобы пользователь случайно выбирал соседнее окно.

## 13. Производительность и надёжность

### 13.1. Требования

- Никакой непрерывный опрос ScreenCaptureKit при закрытом popup.
- Никакого захвата на каждое движение мыши.
- Не блокировать главный поток AX-запросами или снимками.
- Не создавать новые объекты UI целиком при поступлении одного изображения.
- Не запускать параллельно несколько одинаковых запросов захвата.
- Не удерживать закрытые popup и большие изображения без ограничений.
- Не запускать захват при выключенном параметре миниатюр.
- Не использовать частые таймеры для перечисления всех окон всех приложений.

Открытие текстового popup должно происходить независимо от скорости ScreenCaptureKit.

### 13.2. Большое количество окон

Текущий `AccessibilityService` имеет защитный лимит перечисления до 64 окон.

Новая функция не должна обходить этот лимит независимым массовым перечислением.

При большом списке:

- карточки остаются прокручиваемыми;
- приоритет захвата получают видимые элементы;
- число запросов ограничивается;
- ошибки отдельных окон не блокируют список.

### 13.3. Ошибки

Обрабатывать без падения:

- завершение процесса;
- PID reuse;
- закрытие окна;
- изменение названия;
- смену размеров;
- потерю AX-разрешения;
- потерю Screen Recording;
- отказ ScreenCaptureKit;
- выход из полноэкранного режима;
- смену Space;
- подключение и отключение монитора;
- быстрый переход курсора между иконками;
- закрытие popup при незавершённом захвате.

Диагностика должна фиксировать причину ошибки и идентификаторы выполнения, но не содержимое изображений или пользовательские данные окна сверх необходимого.

## 14. Проверки и критерии приёмки

### 14.1. Базовое поведение

1. У приложения с одним управляемым окном режим Automatic открывает popup после задержки.
2. У приложения с несколькими управляемыми окнами режим Automatic открывает popup после задержки.
3. Переопределение Always для приложения открывает popup для одного окна, не меняя настройку других приложений.
4. Режим Disabled отключает автоматический показ, но не команду меню.
5. Незавершённый hover не приводит к открытию.
6. Переход курсора от иконки к popup не закрывает его.
7. Escape закрывает popup.
8. Начало перетаскивания закрывает popup и не нарушает drag-and-drop.

### 14.2. Идентичность

1. Два экземпляра одного `.app` показывают разные списки окон.
2. Закреплённая кнопка сохраняет правильный экземпляр.
3. PID reuse не приводит к выбору окна старого процесса.
4. Два окна с одинаковым названием корректно различаются по доступным признакам либо получают заглушки.
5. Неоднозначное сопоставление не приводит к неверной миниатюре.
6. Закрытие окна во время захвата не обновляет чужую карточку.
7. Закрытие окна перед кликом не переключает произвольное другое окно.

### 14.3. Миниатюры

1. Захватываются реальные изображения окон.
2. Перекрытое окно захватывается независимо, когда это допускает macOS.
3. Свёрнутые и недоступные окна получают заглушки.
4. Отсутствие Screen Recording не блокирует выбор AX-окна.
5. Повторное открытие не выдаёт устаревшее изображение за актуальное.
6. После закрытия popup не продолжается фоновая серия захватов.
7. Быстрая смена иконок не показывает кадры предыдущего экземпляра.

### 14.4. Контекстное меню

1. Пункты организованы по группам.
2. Существующие команды сохраняют семантику.
3. Структура открытого NSMenu не изменяется небезопасным образом.
4. Текстовый список окон и popup используют одну модель идентичности.
5. Команда «Показать окна…» работает при отключённом hover.
6. Принудительное завершение по-прежнему требует подтверждения.

### 14.5. Разрешения

Проверить четыре комбинации:

| Accessibility | Screen Recording | Результат |
|---|---|---|
| Есть | Есть | Список, выбор окон, доступные миниатюры |
| Есть | Нет | Список, выбор окон, заглушки |
| Нет | Есть | Обычные функции Dock, ограниченный режим предпросмотра без индивидуального управления |
| Нет | Нет | Обычные функции Dock |

Запрос Screen Recording не должен появляться от обычного hover.

Отдельно проверить повторный запуск после выдачи разрешения и его отзыв во время работы приложения.

### 14.6. UI

Проверить:

- один и два дисплея;
- Retina и различное масштабирование;
- светлую и тёмную темы;
- русскую и английскую локализации;
- короткие и длинные заголовки;
- переполненную панель WMac;
- обычные Spaces и fullscreen;
- Reduce Motion;
- клавиатуру и VoiceOver.
### 14.7. Автоматические проверки

Использовать существующую инфраструктуру тестов.

Добавить целевые автоматические проверки для:

- правил режима hover;
- сопоставления окон;
- неоднозначных соответствий;
- защиты от устаревшего поколения;
- ограничений кэша;
- миграции настроек.

Реальный ScreenCaptureKit, взаимодействие с TCC и поведение нативного popup проверить на macOS вручную или через существующий интеграционный harness.

Не требуется создавать большой дополнительный набор тестов для очевидной верстки или внутренних деталей AppKit.

## 15. Этапы реализации

### Этап 1. Подготовка модели окон

- Добавить геометрию AX-окон.
- Реализовать безопасное сопоставление.
- Добавить строгий выбор конкретного окна.
- Устранить асинхронное изменение структуры открытого NSMenu.

Результат: безопасная модель окон, независимая от миниатюр.

### Этап 2. Popup

- Реализовать общий контроллер.
- Добавить hover, задержки и закрытие.
- Отображать текстовые карточки.
- Реализовать выбор, клавиатуру и доступность.
- Добавить команду «Показать окна…».

Результат: полноценный выбор окон без ScreenCaptureKit.

### Этап 3. Настоящие миниатюры

- Интегрировать ScreenCaptureKit.
- Добавить разрешения и состояния ошибок.
- Реализовать асинхронный захват.
- Добавить ограничения и кэш.
- Проверить отсутствие неверных соответствий.

Результат: настоящие миниатюры с безопасной деградацией.

### Этап 4. Настройки и завершение

- Добавить глобальные параметры.
- Добавить индивидуальные режимы.
- Мигрировать settings.json.
- Проверить дисплеи, Spaces и локализации.
- Обновить связанные Intent и пользовательскую документацию.

## 16. Что не входит в задачу

- Чтение Dock-меню сторонних приложений.
- Специальная поддержка профилей Terminal.
- Приватные macOS API.
- Управление окнами через CGWindowID.
- Постоянная видеотрансляция содержимого окон.
- Запись скриншотов на диск.
- Сохранение истории содержимого окон.
- Группировка окон по вкладкам браузера.
- Отдельные кнопки для каждого окна на Dock.
- Перемещение окон между Spaces.
- Изменение размеров чужих окон.
- Подмена Mission Control.
- Глобальные системные горячие клавиши.

## 17. Определение завершённости

Доработка считается выполненной, если:

1. Пользователь может увидеть список управляемых окон при наведении на экземпляр.
2. Может выбрать точное окно без ошибочного переключения на другое.
3. Видит настоящие миниатюры там, где macOS позволяет безопасно сопоставить и захватить окно.
4. При отсутствии изображений сохраняет управление окнами.
5. Может открывать тот же список через контекстное меню.
6. Может отключить автоматический hover глобально или для отдельных приложений.
7. Существующие действия Dock, настройки, закрепления и работа нескольких экземпляров не нарушены.
8. Не используются приватные API и не происходит неконтролируемого захвата экрана.
9. Проверки проходят на поддерживаемой матрице macOS, а ограничения платформы объясняются корректно.

**Итог:** WMac получает управляемые карточки конкретных окон с настоящими миниатюрами, сохраняя существующую архитектуру идентичности и управления процессами.
