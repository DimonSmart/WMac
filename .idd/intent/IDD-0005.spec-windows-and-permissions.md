# IDD-0005.spec-windows-and-permissions

## Intent

Окна конкретного экземпляра доступны через его меню и не создают отдельных кнопок панели. Управление использует публичный Accessibility API и корректно деградирует без доступа.

## Поведение окон

Список окон, отслеживание активного окна, восстановление, сворачивание и попытка поднятия относятся к конкретному экземпляру. При выборе окна WMac пытается восстановить его, сделать главным, поднять над окнами того же приложения и активировать соответствующий PID. Системные вспомогательные окна, popover и скрытые технические окна не засоряют список.

Если AX-доступа нет или окно неуправляемо, выполняется активация приложения и показывается ненавязчивое объяснение ограничений. Недоступность окна и ошибки внешнего приложения не приводят к падению или блокировке интерфейса. Последнее активное окно используется при обычном переключении согласно IDD-0003.

Точное соответствие окна нельзя подменять предположением: недокументированные связи Accessibility-объекта и идентификатора графического окна запрещены. Если соответствие нельзя надёжно установить публичными сведениями, WMac не выдаёт приблизительное окно за точное.

## Расположение окон с клавиатуры

Пользователь может включить глобальные сочетания для размещения текущего окна в настройках WMac; по умолчанию они выключены. Пока функция включена и WMac запущен, сочетания действуют на сфокусированное управляемое окно текущего внешнего приложения. Они используют публичный Accessibility API и не меняют окно, если текущую цель нельзя подтвердить или macOS не разрешает нужное действие. При отсутствии Accessibility WMac объясняет, как включить разрешение.

Сочетания зарегистрированы только на время включённой функции; отключение освобождает их. WMac не меняет системные назначения клавиш. Если macOS сообщает конфликт регистрации, все сочетания остаются выключенными, а WMac сообщает о недоступности функции.

Геометрические команды используют видимую рабочую область дисплея, на котором находится текущее окно, с учётом положения меню и Dock:

- Control+Option+←/→ размещают окно в левой/правой половине; Control+Option+↑/↓ — в верхней/нижней половине.
- Control+Option+U/I/J/K размещают окно в верхнем левом/верхнем правом/нижнем левом/нижнем правом углу.
- Control+Option+D/F/G выбирают левую/среднюю/правую треть; Control+Option+E/R/T — левую/среднюю/правую область шириной в две трети.
- Control+Option+Enter разворачивает окно на всю видимую рабочую область. Control+Option+Shift+↑ растягивает его по высоте, сохраняя горизонтальное положение и ширину.
- Control+Option+= и Control+Option+- увеличивают или уменьшают размер окна пропорционально, сохраняя его центр и удерживая окно в видимой рабочей области.
- Control+Option+C центрирует окно без изменения размера.
- Control+Option+Backspace восстанавливает размеры и положение окна до первого изменения сочетаниями за текущий сеанс WMac. Исходная геометрия хранится только в памяти.

Команды применяются только к текущему окну и не перемещают его между Spaces. Неудачное или частичное изменение не приводит к падению WMac и не перенаправляется на другое окно.

## Разрешения

Accessibility запрашивается при первом обращении к управлению окнами, с объяснением и кнопкой перехода к системным настройкам. Повторные запросы без действия пользователя не допускаются. Настройки показывают состояние доступа и отсутствующие функции.

Без Accessibility продолжают работать список процессов, закрепления, обычный запуск, запрос нового экземпляра, переключение по PID и завершение процесса. Операции отдельных окон недоступны или ограничены; старт панели не ждёт разрешения.

Preview/thumbnail и ScreenCaptureKit не входят в MVP. Запрос Screen Recording в первой версии запрещён. Допустимо предусмотреть место для будущей функции, не включая её в MVP.

## Приёмка и проверка

С доступом проверяются список и выбор нескольких окон одного процесса, восстановление, сворачивание и активация нужного PID. Без доступа проверяется весь сохранённый набор процессных функций и понятная деградация оконных действий. Также проверяются исчезновение окна во время действия, неуправляемое окно, отказ в доступе и отсутствие повторных запросов или запроса Screen Recording. Для сочетаний проверяются регистрация только при включённой настройке, снятие регистрации после отключения, применение к сфокусированному окну на одном и нескольких дисплеях, отказ без изменения чужой цели при отсутствии Accessibility, конфликт сочетания и восстановление исходной геометрии. Связанные контракты: IDD-0002, IDD-0003, IDD-0004, IDD-0007.

## Расширение после MVP — IDD-0010

Исходный запрет Screen Recording относится только к MVP. Для новых добровольно включённых миниатюр IDD-0010 допускает исключительно публичные ScreenCaptureKit API и запрос разрешения после явного действия пользователя. Отсутствие этого разрешения не ограничивает AX-управление. При выборе конкретного окна из popup или текстового меню запрещается неявная активация произвольного другого окна либо процесса вместо отсутствующего целевого окна. Деградация к активации PID остаётся только для обычного переключения через кнопку.
