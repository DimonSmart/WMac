# IDD-0008.spec-quality-and-release

## Intent

WMac работает локально без аккаунта, телеметрии и сбора содержимого окон. Диагностические логи локальны и не содержат содержимого пользовательских документов. Ограничения сторонних приложений и macOS ясно объясняются пользователю, а не скрываются обходными хаками.

## Измеримые цели

- Холодный старт до панели — целевые ≤2 секунд на типичном поддерживаемом Mac без ожидания Accessibility.
- Обновление после уведомления запуска/завершения — целевые ≤500 мс при штатной нагрузке; длительность запуска стороннего приложения сюда не входит.
- Стандартная навигация — целевые 60 FPS; внешние API не блокируют главный поток.
- Память в покое без preview — ориентир ≤120 МБ при 30 GUI-процессах и двух панелях, измеряемый на реальном устройстве.

Это проверяемые цели, а не гарантии для любых машин и сторонних приложений. Пустой список, невалидный bookmark, недоступные окна, отсутствие Accessibility, быстрая смена мониторов и PID reuse не приводят к падению.

## Доступность

Кнопки и меню поддерживают VoiceOver. Настройки и поиск доступны с клавиатуры. Учитывается системное Reduce Motion. RU/EN интерфейс, темы, Retina и минимальные цели ввода определены в IDD-0003.

## Поставка

Поддерживаются macOS 14.0+ и universal arm64 + x86_64. Release распространяется через GitHub Releases как DMG с перетаскиванием в Applications. Developer ID Application подпись, notarization и stapling не требуются для MVP. Отображаемое имя — WMac!; bundle identity стабильна.

Загруженное приложение может потребовать штатного подтверждения первого запуска в macOS; беспрепятственное открытие двойным кликом на любом стандартно настроенном Mac не гарантируется. Условия первого запуска и отсутствие notarization явно описываются пользователю. WMac не отключает Gatekeeper, не снимает quarantine и не изменяет системное доверие автоматически. После разрешённого системой запуска основные сценарии приложения не требуют Terminal.

## Локальная разработка и идентификация сборки

Пользователь может установить текущий стабильный релиз из официального GitHub репозитория командой и отдельно собрать и запустить локальную Debug-версию. Команды запуска выбирают точный путь приложения и штатно завершают другую запущенную копию WMac перед запуском, чтобы не оставлять старую панель на экране. Если завершение не удалось, новая копия не запускается.

Локальная Debug-версия явно отличается меткой L в menu bar и значке приложения. About показывает Debug/Release, версию, номер сборки и фактический путь приложения. Стабильная bundle identity, настройки, закрепления и правила разрешений сохраняются; одновременно работающие панели двух копий не являются целевым сценарием.

Установка командой проверяет официальный пакет и контрольную сумму до замены приложения, сохраняет предыдущую установленную копию и не изменяет системные механизмы доверия. Проверка различий охватывает локальный запуск после установки релиза, возврат к установленной версии и отсутствие оставшегося старого процесса.

## Обновления

WMac асинхронно проверяет стабильные GitHub Releases при запуске и раз в сутки. Пользователь может отключить фоновые проверки и проверить новую версию вручную из меню WMac. Debug-сборки не проверяют обновления автоматически. Сеть используется только для метаданных релиза и загрузки выбранного обновления; данные окон, закреплений и настроек не отправляются.

Новая версия предлагается пользователю; установка начинается только по его действию. Для установленного в доступный для записи Applications приложения WMac загружает официальный DMG, проверяет SHA-256 из метаданных GitHub, подпись bundle, идентичность и версию, заменяет приложение и перезапускается. Предыдущая копия сохраняется для восстановления при ошибке замены или запуска. Запуск из DMG, build-каталога или недоступного для записи места сопровождается объяснением и переходом на страницу релиза для ручной установки. Отсутствие сети, релиза или корректного пакета не мешает работе панели; ручная проверка явно сообщает результат. Одновременные проверки и установки исключены.

Обновление сохраняет настройки и закрепления, ожидает их сохранения и восстанавливает Dock перед перезапуском. WMac не снимает quarantine и не меняет Gatekeeper; системное подтверждение запуска и повторное предоставление Accessibility после изменения ad-hoc подписи могут потребоваться. Автоматический откат после последующего сбоя новой версии не гарантируется; формат данных допускает миграции по IDD-0007.

Проверка охватывает сравнение версий, отбрасывание prerelease/draft и чужих URL, отсутствие/повреждение пакета, SHA-256, безопасную замену с восстановлением при ошибке и отсутствие потери пользовательских данных. Полный сценарий установки и перезапуска проверяется на отдельной копии приложения в macOS.

## Доказательства приёмки

Автоматическая проверка охватывает применение снимков процессов, PID reuse, связывание Pin и стабильный порядок, два одновременных запуска, ошибочный callback, истёкший bookmark и восстановление настроек. Интеграция на macOS подтверждает реальные PID тестового GUI `.app`, допускающего несколько процессов, и управление тестовыми окнами с Accessibility и без него. UI-проверка охватывает обычный, Shift, средний и правый клики, меню окон, закрепление/открепление и настройки. В репозитории имеется исполняемый набор тестов.

Ручная матрица: macOS 14, 15 и доступные более новые версии; Apple Silicon и Intel; один/два монитора; светлая/тёмная тема; Accessibility вкл./выкл.; обычные Spaces и fullscreen. Подключение/отключение монитора проверяется вручную при отсутствии оборудования в CI. Finder, Safari, Chrome, Terminal, VS Code и TextEdit проверяются без предположения, что каждый поддерживает несколько процессов. Неизбежные ограничения ясно сообщаются пользователю.

MVP требует одновременного выполнения IDD-0001, IDD-0002, IDD-0003, IDD-0004, IDD-0005, IDD-0006 и IDD-0007: отдельные кнопки процессов и точная активация, три реальных PID, отсутствие ложного успеха single-instance приложения, сохранение закреплений, деградация без AX, два монитора, доступный Dock и выход через menu bar, автозапуск из UI и DMG для GitHub Releases с ясно описанными условиями первого запуска. Производительность и доступность оцениваются на соответствующей матрице.

## Расширение проверок — IDD-0010

Для предпросмотра окон дополнительно проверяются задержки/жизненный цикл popup, строгая идентичность AX и SC окон, отбрасывание неоднозначных миниатюр, отзыв разрешений и устойчивость при закрытии окон и отключении дисплеев. Снимки ScreenCaptureKit остаются только в памяти. Приёмка на реальной macOS и тесты модели определены IDD-0010.
