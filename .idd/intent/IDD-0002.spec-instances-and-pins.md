# IDD-0002.spec-instances-and-pins

## Intent

Общая модель идентичности обеспечивает однозначное соответствие между реальными экземплярами приложений, закреплениями и кнопками всех панелей.

## Идентичность и список процессов

- AppDefinition — установленный `.app` с URL, bundle identifier, отображаемым именем и значком. Идентичность — сочетание bundle identifier и канонического bundle URL; разные пути с одинаковым bundle ID автоматически не объединяются.
- AppInstance — отдельный GUI-процесс с собственным PID. Его ключ в памяти — `(PID, processStartTime)`, где `processStartTime` — надёжное время создания текущей жизни процесса, доступное от macOS. Если для приложения без установленного `.app` нет даты LaunchServices, но macOS сообщает время создания процесса, экземпляр сохраняет ту же идентичность и показывается на панели. Один PID не является постоянной идентичностью и не переносится между сессиями.
- Window принадлежит конкретному экземпляру и используется для меню и переключения, не для дополнительных кнопок.
- Pin — постоянная запись AppDefinition, не PID. Временная кнопка связана с одним экземпляром; вместо неё этот экземпляр может представлять закреплённая кнопка.

На каждой видимой панели каждый отображаемый AppInstance представлен ровно одной кнопкой. Имя, иконка, bundle ID и URL сами по себе не идентифицируют экземпляр. Показываются GUI-приложения с regular activation policy, включая запущенные напрямую из командной строки и приложения без окон. Процесс без корректного `.app` остаётся временной кнопкой и не может стать Pin. Фоновые агенты, служебные процессы, WMac и приложения только в menu bar по умолчанию исключены; пользовательские исключения определены в IDD-0007.

Активная подсветка относится строго к выбранному процессу. Одинаковые приложения имеют отдельные кнопки с одинаковой основной иконкой. Tooltip различает имя и порядковый номер экземпляра; PID доступен в сведениях контекстного меню. Порядок временных кнопок стабилен при переключении приложений. Любую кнопку, включая незакреплённый работающий процесс, можно переставить мышью или через контекстное меню. Координатор сохраняет относительный порядок между закреплёнными и временными кнопками.

Начальный список включает уже работающие процессы. События и редкая сверка реального состояния исправляют пропуски, в том числе после пробуждения и разблокировки. Перезапуск WMac заново обнаруживает действующие экземпляры. Завершившийся процесс больше не получает действий и подсветки. Смена URL, отсутствие bundle ID, иконки или даты LaunchServices, PID reuse и завершение между снимком и действием обрабатываются без падения и ошибочной привязки. Если macOS не предоставляет надёжное время жизни процесса, WMac не привязывает к его PID действия, которые могли бы попасть в другой процесс.

## Закрепления

Добавление доступно перетаскиванием `.app` из Finder и через «Приложения» → «Закрепить». Контекстное меню позволяет открепить. Перетаскивание закреплённых и работающих незакреплённых кнопок меняет единый сохраняемый порядок.

В Finder принимаются только корректные GUI-приложения. Повторное добавление того же канонического приложения не создаёт второй Pin. Если в одном перетаскивании есть некорректные элементы, не применяется ни часть списка. Добавление Pin не запускает приложение и не меняет активное приложение.

Переставлять можно любые отображаемые кнопки. Незавершённое перетаскивание не меняет порядок и не запускает, не активирует и не завершает приложение. Сохранённый порядок согласован на всех видимых панелях и восстанавливается после перезапуска.

Постоянное расположение выражено последовательностью логических слотов, а не экранными координатами. Слот закрепления ссылается на UUID Pin. Слот незакреплённого приложения ссылается на AppDefinition и собственный UUID слота; одно приложение может иметь несколько слотов для одновременно работающих экземпляров. Освободившийся слот остаётся в модели и повторно используется после следующего запуска приложения, но пустая кнопка на панели не рисуется. Если идентичность AppDefinition отсутствует, кнопку можно двигать в текущей сессии без сохранения PID на диск. После перезапуска WMac или процесса точное сопоставление нескольких экземпляров одного приложения не гарантируется: свободные слоты назначаются стабильно по порядку обнаружения. Новые приложения без сохранённых слотов добавляются справа.

Закрепление или открепление работающего приложения не должно изменять видимую позицию его кнопки. Релинк Pin сохраняет слот и UUID закрепления. Исключение приложения скрывает кнопки без уничтожения сохранённых позиций. Сохранённые слоты разделяются между экранами и не содержат PID или время старта процесса.

Незапущенное закреплённое приложение имеет одну кнопку; обычный клик запускает его. Первый появившийся экземпляр занимает эту кнопку без дублирования, следующие получают собственные временные кнопки на восстановленных позициях либо справа, если позиций ещё нет. Если приложение закрепляется при нескольких процессах, выбирается активный экземпляр, а при его отсутствии — самый ранний доступный; остальные остаются отдельными.

При завершении закреплённого экземпляра Pin представляет самый ранний оставшийся, его прежняя временная кнопка удаляется. При отсутствии процессов Pin становится незапущенным. Завершение других процессов удаляет только их временные кнопки, сохраняя Pin и остальных экземпляров.

Перемещённое или удалённое `.app` не удаляет Pin молча: отображается «приложение не найдено», доступны новый путь и открепление. При необходимости для восстановления URL сохраняется bookmark; постоянные данные регулирует IDD-0007.

Замена приложения в существующем Pin сохраняет его идентичность и место в порядке. Отмена выбора, некорректное приложение или дубликат не заменяют исходную запись.

## Приёмка и проверка

Проверяются начальные и повторные снимки, пропущенные события, повторное использование PID, несколько одинаковых bundle ID по разным путям, процессы без окон и неполные метаданные. Регулярное GUI-приложение, запущенное напрямую из командной строки без даты LaunchServices, отображается отдельной временной кнопкой и активируется по своему PID, если macOS предоставляет время создания процесса. При завершении такого процесса кнопка исчезает, а повторно использованный PID не наследует его действия. При трёх экземплярах закрепление, активация и последовательное завершение сохраняют инвариант одной кнопки на экземпляр на каждой панели и стабильный порядок остальных кнопок. Перезапуск восстанавливает закрепления и порядок приложений, но заново обнаруживает процессы и назначает их по доступным слотам. Запуск описан в IDD-0004, поведение кнопок — в IDD-0003.

Отдельно проверяются добавление корректного `.app` из Finder без его запуска, игнорирование дубля, атомарный отказ для смешанного корректного и некорректного набора, перестановка закреплённых и временных кнопок и отсутствие побочного действия при отменённом перетаскивании. Перестановка и замена сохраняют идентичность и порядок Pin через перезапуск; отмена, некорректная или дублирующая замена сохраняет исходную запись.
